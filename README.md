# Credit Scoring Engine — India Edition

An end-to-end machine learning system that scores Indian loan/credit
applicants: raw applicant data in, a **CIBIL-style 300–900 credit score**,
a risk grade (A–E), a default probability, an approve/decline
recommendation, and a plain-English explanation of the top factors — out.

Adapted for the Indian market: INR income, employment type (Salaried /
Self-Employed / Business Owner), city tier (Metro / Tier-2 / Tier-3),
existing EMI burden, number of dependents, and Indian loan purposes (home
loan, personal loan, vehicle loan, education loan, gold loan, business loan,
credit card, consumer durable).

---

## Where the data comes from

**The data shipped with this project (`data/credit_data.csv`) is synthetic**
— generated by `data/generate_data.py` using realistic statistical
distributions and correlations for the Indian market (income by city tier,
debt-to-income, credit utilization, late payments, etc.). It is **not** real
bank or CIBIL data — no one can legally hand out real customer credit
records, so every public "credit scoring" tutorial/project you'll find
(including this one) either uses synthetic data or one of the datasets below.

**If you want to train on real data instead**, here are actual public
Indian credit/loan datasets you can substitute in:

| Dataset | Where |
|---|---|
| Leading Indian Bank & CIBIL Real-World Dataset | [Kaggle](https://www.kaggle.com/datasets/saurabhbadole/leading-indian-bank-and-cibil-real-world-dataset) |
| Loan Prediction India | [Kaggle](https://www.kaggle.com/datasets/bhavyamashru/loan-prediction-india) |
| Credit/Loan Dataset — Rural India | [Kaggle](https://www.kaggle.com/datasets/heydido/creditloan-dataset-rural-india) |
| India Wilful Loan Defaulters | [Kaggle](https://www.kaggle.com/datasets/ratnadeepjoshi/india-loan-defaulters) |
| Home Credit Default Risk (Home Credit operates extensively in India) | [Kaggle](https://www.kaggle.com/c/home-credit-default-risk) |

To use one: download the CSV, rename/remap its columns to match the feature
names in `src/preprocessing.py` (or edit that file to match the new
columns), point `src/train_model.py`'s `DATA_PATH` at it, and retrain.

## Run it (3 steps)

### Step 1 — Generate the dataset
```bash
python data/generate_data.py
```
Creates `data/credit_data.csv` with 15,000 synthetic Indian applicants
(~23% default rate), including city tier, employment type, existing EMI
burden, and Indian loan purposes.

### Step 2 — Train the model
```bash
python src/train_model.py
```
Trains Logistic Regression, Random Forest, and Gradient Boosting, prints
ROC-AUC / accuracy / classification report for each, picks the best by
ROC-AUC, and saves it to `models/`.

### Step 3 — Score applicants

**A) Command line**
```bash
python cli.py --demo
python cli.py --json path/to/applicant.json
```

**B) REST API**
```bash
uvicorn api.app:app --reload --port 8000
```
Then open:
- `http://localhost:8000/` — demo form (₹ amounts, Indian dropdowns)
- `http://localhost:8000/docs` — interactive Swagger API docs

Example request:
```bash
curl -X POST http://localhost:8000/score \
  -H "Content-Type: application/json" \
  -d '{
    "age": 32,
    "annual_income": 900000,
    "city_tier": "Metro",
    "employment_type": "Salaried",
    "employment_length_years": 6,
```

## How the credit score is calculated

1. The trained classifier outputs a **probability of default** (0–1).
2. That's converted to a **300–900 score** (the range CIBIL, Experian, and
   Equifax use in India) via a log-odds transform: `score = 580 + 75 * ln((1-p)/p)`,
   clipped to [300, 900]. This is calibrated against this model's actual
   predicted-probability distribution on the training population, so scores
   are spread meaningfully across the range rather than clustering.
3. Score bands mirror how CIBIL scores are commonly described to consumers:

   | Score | Grade | Label |
   |---|---|---|
   | 750–900 | A | Excellent |
   | 700–749 | B | Good |
   | 650–699 | C | Fair |
   | 600–649 | D | Poor |
   | 300–599 | E | Very Poor |

4. **Explanations** rank features by combining the model's global feature
   importance with how far the applicant's standardized values deviate from
   average, in the risk-increasing direction.

## Extending this project

- **Real data**: see the dataset table above; remap columns in
  `src/preprocessing.py` to match.
- **Regional nuance**: add state, rural/urban flag, or bureau-reported
  fields (e.g. actual CIBIL/Experian score, if you have API access to one
  of India's four licensed credit bureaus — CIBIL, Experian, Equifax, CRIF
  High Mark) as additional features.
- **Better explainability**: swap `_explain()` in `src/scoring.py` for
  [SHAP](https://github.com/shap/shap) values.
- **Regulatory alignment**: real credit decisioning in India must comply
  with RBI's Fair Practices Code and, for scored lending, provide reasons
  for rejection — the `top_factors` output here is a starting point for
  that, not a compliance-ready implementation.

---

## Important disclaimer

This is a **portfolio / educational project** using **synthetic data**. It
does not connect to CIBIL, Experian, Equifax, or CRIF High Mark, and its
scores are not real bureau scores. Production credit underwriting in India
is regulated by the RBI and requires licensed bureau integration, fairness
audits, and model governance well beyond what's shown here.
